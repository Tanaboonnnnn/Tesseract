# ISO Phase 1 Implementation Plan

**Goal:** Prove a subject-independent visual authoring contract without introducing a new writer or renderer.
**Spec:** SPEC §4.16 and the approved Phase 0 decisions; DESIGN.md controls style in Phase 2.
**Architecture:** Core owns the strict data catalog, validation, projected bounds and step resolution. The existing MCP format tool exposes a bounded authoring preview. Add no persisted visual type to current client unions while the renderer and release gate are still pending.

- [x] Establish a failing core test suite for both pack examples, each validation rule and frame resolution.
- [x] Implement a data-only catalog and strict, bounded validation without React, browser APIs or store access.
- [x] Check the remote tool list is unchanged, the selected pack is the only expanded format, and preview data cannot be saved or staged in v1.
- [x] Run the full test and typecheck gates, inspect the diff and stop before Phase 2.

**Review focus:** Keep 64,000 actual UTF-8 bytes distinct from the existing legacy YAML character check; validate before accepting a scene. Count only explicit effective edits, including changes in focus, not the player's implied dimming. Keep explicit state patches persistent, and use a null cutaway to close it. Do not make an old visual file unreadable by activating the new write path yet. Tests use synthetic fixtures only.

**Gate:** Core and MCP tests observed failing before implementation. Full suite: 260 passed, 1 Windows-only test skipped on Linux. Typecheck passed. The existing remote tool names, save path and Classroom v1 allowlist are unchanged. This is an authoring preview, not a released or writable visual type.
